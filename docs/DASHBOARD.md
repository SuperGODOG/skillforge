# SkillForge 本地证据看板

看板把已有执行记录、经历、候选与实验结果放到同一个只读界面中。它不会启动模型、修改任务状态或批准技能发布。

## 启动

在项目根目录执行：

```bash
.venv/bin/python -m skillforge.dashboard --root . --port 8765
```

打开终端打印的本地地址。按 `Ctrl+C` 关闭服务。服务仅绑定本机回环地址，不适合直接暴露到公网。

默认读取 `runs/`、`scratch/` 中的支持格式，以及：

- `docs/p6_logistics_abc_raw_results.json`
- `docs/p6_real_model_abc_raw_results.json`

如需缩小扫描范围，可重复指定项目内的数据目录：

```bash
.venv/bin/python -m skillforge.dashboard --root . \
  --data-dir scratch/pi_live_smoke_phase5a --port 8765
```

目录必须在项目内部。固定的两份 P6 报告仍作为实验档案读取。页面通过“刷新记录”重新读取数据；不使用自动轮询。

## 导出离线看板

把当前记录保存为一份可直接双击打开的 HTML：

```bash
.venv/bin/python -m skillforge.dashboard --root . \
  --export-html scratch/dashboard-acceptance/evidence-share.html
# 已安装 CLI 时也可：
skillforge --root . dashboard --export-html scratch/dashboard-acceptance/evidence-share.html
```

导出仅读取证据投影，不启动服务、模型或发布流程。HTML 内含快照、样式与脚本，断网后仍可切换三页、筛选记录和展开已有证据；页面显示快照时间，刷新按钮禁用。它不会获取之后产生的新记录。更新时使用另一个输出文件名，已有目标不会被覆盖。

输出必须是项目内的 `.html` 文件；越界或符号链接路径会被拒绝。读取范围仍遵循 `--data-dir` 和固定历史档案规则。页面采用现有已知字段脱敏；分享前审阅业务回答和工具结果，确认适合公开。浏览器需启用 JavaScript。导出不修改原始实验成绩，复核说明与未知项一起保留。

## 三分钟讲解顺序

1. **运行证据（约一分钟）**：打开一次失败任务，说明用户目标、冻结的版本正文、实际工具轨迹及 Oracle 为什么判失败。执行完成和业务合格分开解释。
2. **技能演进（约一分钟）**：选择完整演示目录中的数据库候选，从两条来源 Episode 进入原运行，对比 `1.0.0` 基线与 `1.0.1` 候选，再查看 RepairJob、回归、确认晋升和新任务实际复用。
3. **评测对照（约一分钟）**：先看三组对照如何计算改善与退化，再切换 D5 真实模型记录，解释原 DEV B 2/3 中的 Oracle 误报、单独离线复核，以及 C 未生成所以保持未知。

第二步的完整链路来自 scripted 响应与 synthetic 订单，执行与治理组件实际运行；D5 则是实际模型生成与执行。分别展示，能够讲清“机制如何工作”和“模型实际表现如何”。D5 真实 V2 修补仍未验证。

## 生成一套完整演进演示

```bash
env -u PI_SOURCE_ROOT .venv/bin/python -m skillforge.scenarios.dashboard_evolution_demo --output-dir runs
```

每次新建 `runs/dashboard_evolution_<uuid>/`，保存四个 SQLite、逐阶段原子更新的 `report.json`、技能与临时 Git 仓库。不会覆盖前一次记录；这些运行产物不纳入项目版本控制。失败时报告保存失败阶段与已经完成的任务，不把半成品当作成功。

刷新看板后，在“技能演进”搜索 `logistics_query`，选择来自该目录的数据库候选，依次查看：

1. 两条来源失败 Episode，展开后跳转到原始工具轨迹与业务回答。
2. 原正式版 `1.0.0` 的执行快照与修订候选 `1.0.1` 的正文对比。
3. RepairJob 归因与一次修补尝试，以及覆盖正常订单、全签收遗漏与部分签收场景的回归记录。
4. 权威验证的内容、配置、数据集绑定与临时库发布记录。
5. 新任务自动检索 `1.0.1` 后的执行和新 Episode；旧运行仍冻结在 `1.0.0`。

这是 **scripted 模型 + synthetic 订单 + 实际 Pi 执行链** 的机制演示。基线是预置夹具，修补文本是固定脚本；同一脚本不会因 Skill 正文改变而自动呈现效果差异。晋升包含先验证未确认被拒、再在隔离演示库中显式确认的流程；不是对用户正式技能库的发布。真实模型效果和本轮 OS 级隔离未在此演示中验证。

## 三条阅读路径

### 运行证据

选择任务，查看冻结的 Skill 正文、版本与意图绑定、工具输入输出、错误、独立 Oracle 和 Collector 回收的 Episode。

`COMPLETED` 表示执行状态；业务是否合格看 Oracle。两者单独展示。真实模型与受控模型响应也单独标注；合成业务工具不等于真实电商系统。

状态来自持久化记录，不是进程存活探针。首页统计的是载入记录数，不将不同来源的复核快照当作新的独立业务样本。

### 技能演进

以候选为入口，沿真实的来源 Episode ID、父候选 ID、验证记录及发布 ID 查看演进关系。没有关联凭据时显示“未找到”或“未记录”，不按相同 Skill 名字猜测血缘。

数据库中权威候选与实验报告中的版本摘要要区分。报告正文若只有预览，不应被当作完整执行正文；报告中的“成功”也不能替代当前 CandidateStore 的验证与晋升凭证。

没有父 Candidate ID 时，若来源 Episode 的实际运行版本匹配验证基线，可展示“基线执行快照”，不补造父候选。后续复用必须同时具备同范围内的检索命中记录、相符的发布版本及完整正文；同名 Skill、相似正文或正文预览不足以建立关联。

### 评测对照

选择实验与分区，查看 A 无 Skill、B 原版、C 候选的逐任务结果及 B→C 配对改善、退化、不变和不可配对项。

- 真实模型、scripted、探索性重分区、事后挑战是不同档案，不合并计算效果。
- “原报告汇总”与“逐任务可核验结果”分开展示；缺少明细的组不会按汇总填出回答或通过标记。
- 开发集与锁定评测集分别显示，血缘与分区说明以原始记录为依据。
- 没有真实 usage 或账单的数据保持未采集；SDK 的占位零费用不表示免费调用。

表格保留原记录的判定和失败原因；看板不重新给历史回答评分。同目录 `acceptance_review.json` 可以给准确的 `report.json` 附上复核告知，原成绩不变，离线改判另存。本地 D5 档案包含一次已确认的 Oracle 误报及“未生成 V2”说明；复核数字不能当作新的前瞻性实验成绩。

## 数据与访问边界

- SQLite 使用只读连接，不调用业务 Store 初始化、迁移或 Runtime 恢复逻辑。
- 只提供固定页面与只读快照接口，不提供任意文件浏览、SQL 执行、任务启动或发布接口。
- 读取范围、深度、文件大小和记录数有上限；截断、损坏文件与旧字段缺失显示提示。
- 页面将工具输出、模型回答、Skill 正文当作普通文本显示，不执行其中的 HTML 或脚本。
- 不读取 Pi 的凭据配置，不显示模型原始思维过程。既有业务记录仍可能含内部信息，应按本地开发资料管理。

看板用于追溯已有证据，不把历史记录转换成新验收结论。验证命令与本轮验收结果见 [实现与验收记录](DASHBOARD_WALKTHROUGH.md)。
